# CloudVision AI — этап 7. Разбираемся с тонкими облаками

Цель: проверить, какой вклад в ложные срабатывания вносит класс **2 — thin cloud**, и подготовить больше **качественной ручной разметки** для следующего этапа обучения.

## Установка

Скопируй `experiment_cloud_classes.py` и `label_more.py` в корень **существующего** проекта, а `tests/test_class_policy.py` — в его папку `tests`. Не замени существующие файлы и не удаляй снимки.

Среда `venv` из этапов 1–6 подходит. Новый `pip install` не нужен.

## Запуск (Windows 11)

```powershell
.\.venv\Scripts\python.exe experiment_cloud_classes.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Результаты:
- `reports/class_policy_experiment/results.csv` — доля плотных/тонких облаков и сравнение двух вариантов подсчёта.
- `reports/class_policy_experiment/previews/` — наглядное сравнение исходного изображения с двумя политиками подсчёта.

**Важно:** вариант «только плотные облака» — диагностический. В финальной версии задания СПУТНИКС нужно учитывать и тонкие облака, а не искусственно занижать облачность.

## Дополнительная разметка (рекомендовано)

```powershell
.\.venv\Scripts\python.exe label_more.py
```

Для повторного открытия уже размеченных изображений:

```powershell
.\.venv\Scripts\python.exe label_more.py --all
```

**Правила:**
1. Выделяй весь участок облака кистью, а не только его границы или несколько линий.
2. Тени облаков, снег, светлый песок, воду и светлые скалы не отмечай как облака.
3. Пустую маску сохраняй лишь если кадр проверен и на нём действительно нет облаков.
4. Для учебной проверки собери хотя бы 8–12 **разнообразных** размеченных изображений, по возможности включив снимки с облачностью более 75%. Это ориентир для пилота, а не гарантия достаточной выборки.
5. Для надёжной оценки выдели отдельные изображения, которые **не будут участвовать в настройке модели**. Не используй одну и ту же проверочную тройку для бесконечной подгонки параметров.

Разметка сохраняется в `reports/labels`; оригиналы не меняются. Данные и отчёты лучше не публиковать в GitHub, код публиковать можно.
