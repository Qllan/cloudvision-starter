# CloudVision AI v4 — обучение U-Net на проверенных масках СПУТНИКС

## Исходные данные

- 4207 RGB-фотографий в data/new_raw (одна extra-папка не распакована).
- Зафиксированный CSV: reports/selection_v4/selection.csv:
  35 TRAIN, 10 VAL, 5 TEST.
- Проверенные ручные маски всех 45 TRAIN/VAL: data/verified_v4/.
- Старые снимки и маски (опционально): data/input и reports/labels.
- Старое разбиение: reports/training/dataset_split.csv. Используем **только**
  старый TRAIN; старый VAL/TEST не используются для обучения.
- Начальная модель: models/cloudvision_unet_v3_policy.pt.

**TEST не открывается в этом этапе** и не используется в выборе эпохи,
параметров или оценке улучшений. Скрипт проверяет группы старой и новой
выборки и останавливается при их пересечении. При ошибке пришли лог, не
удаляй/не меняй CSV разбиения ради прохождения проверки.

Проверь разметку:

    .\.venv\Scripts\python.exe audit_v4_labels.py

Должно быть: сохранено корректных 45; нет масок 0; некорректных 0.
Число «стоит перепроверить» — предупреждение, не ошибка формата.
Убедись, что 3 снимка со сменой решения >75% просмотрены внимательно.

## Шаг 1. Короткая проверка GPU и обучения (не затрагивает v3)

    .\.venv\Scripts\python.exe train_cloudvision_v4.py --device cuda --epochs 2 --model models/cloudvision_unet_v4_smoke.pt --out reports/training_v4_smoke

Два прохода по TRAIN, проверка на новой VAL. Вывод: эпохи,
VAL MAE (процентных пунктов), IoU и точность решения по порогу 75%.

Если прежнее разбиение TRAIN/VAL/TEST отсутствует либо старые данные
недоступны, можно **отдельно** проверить режим только новых масок:

    .\.venv\Scripts\python.exe train_cloudvision_v4.py --device cuda --epochs 2 --no-old-train --model models/cloudvision_unet_v4_smoke_newonly.pt --out reports/training_v4_smoke_newonly

Этот вариант имеет всего 35 TRAIN. Он полезен для проверки кода,
но обучающее разнообразие может оказаться слишком маленьким.
Отдельно оцени качество до выбора финального режима.

## Шаг 2. Обучение v4

После проверки smoke-теста:

    .\.venv\Scripts\python.exe train_cloudvision_v4.py --device cuda --epochs 25 --size 256 --batch-size 4 --model models/cloudvision_unet_v4_policy.pt --out reports/training_v4

Скрипт начинает с весов v3 Policy и дообучает всю сеть,
используя небольшое изменение яркости/контраста и повышенный вес
новых снимков (вес 3 против веса 1 старых).
Для выбора лучшей эпохи использует новую VAL; есть ранняя остановка
после восьми эпох без улучшения.

Не используй флаг --overwrite без необходимости:
он заменяет ранее сохранённую модель v4. Старую v3 он заменить не может.

Результаты:
- models/cloudvision_unet_v4_policy.pt — новый checkpoint с epoch, size, version.
- reports/training_v4/training_history.csv — динамика обучения по эпохам.
- reports/training_v4/baseline_v3_validation_predictions.csv — старый v3 на
  новой VAL в исходном разрешении.
- reports/training_v4/validation_predictions_v4.csv — выбранный v4 на той
  же VAL в исходном разрешении.
- reports/training_v4/model_comparison.csv — сравнение MAE, IoU и точности
  решений по правилу **строго >75%**.
- reports/training_v4/validation_previews — несколько сравнений масок.

Итоговое сравнение считается на одних и тех же десяти RGB/масках VAL,
с восстановлением прогноза к исходному разрешению изображения. Это
**валидационная оценка**, а не независимый тест и не доказательство
успешной работы на всех 4207 кадрах.

## Шаг 3. Предпросмотр новой модели без удаления файлов

После обучения:

    .\.venv\Scripts\python.exe run_batch_v4.py --input data/new_raw --out reports/batch_v4_model --model models/cloudvision_unet_v4_policy.pt --device cuda --manifest reports/selection_v4/selection.csv --splits train,val --limit 5

Сохраняются новые маски и отчет. Исходные снимки не меняются.
TEST по-прежнему не используется.

## Известные ограничения

- Архитектура TinyUNet остаётся компактной, хоть вход увеличен до 256.
- На десятке VAL точность имеет большую статистическую неопределённость.
- VAL используется для выбора лучшей эпохи. Для окончательной оценки
  нужны пять независимых TEST с новыми эталонными масками, вручную
  подготовленными *без подсказки модели* после фиксации checkpoint.
- Если снимок содержит космос вне Земли, необходимо согласовать
  определение облачности с условиями конкурса до финальной оценки.
- Выбросы и необычные фотографии (терракота, океан, граница Земли)
  должны оставаться в данных: не скрывай неудачные примеры из отчёта.
- Не загружай исходные изображения, локальные маски или веса в GitHub.
