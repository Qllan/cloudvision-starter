# Обслуживание репозитория CloudVision AI (ноябрь 2026)

## Результат рефакторинга

- Общая загрузка checkpoint и построение бинарной маски перенесены в \`cloudvision/inference.py\`.
- \`run_batch_v4.py\`, \`evaluate_v4_holdout.py\`, \`evaluate_v5_holdout.py\`,
  \`compare_cloud_heavy_models.py\` теперь не зависят от демонстрационного
  CLI \`run_competition_demo.py\`, содержащего отдельную функцию удаления
  **только рабочих копий**. Сам демонстрационный скрипт импортирует
  общую реализацию для обратной совместимости.
- Оставлены прежние letterbox-обработка, порог бинаризации 0.5 и
  исходный размер выходной маски — нельзя менять исторические
  замороженные модели/TEST под видом «рефакторинга».
- CI проверяет все Python-файлы, запускает основной набор тестов и
  архитектурный тест на отсутствие операций удаления в инференсе.

## Что удалено из Git

**15 устаревших текстовых файлов:** \`README_STAGE3.md\` …
\`README_STAGE14.md\`, \`STAGE2_README.md\`,
\`ADDITIONS_TO_GITIGNORE.txt\`, \`GITIGNORE_ADDITIONS.txt\`.

Эти файлы были промежуточными заметками разных стадий. Их содержание
**сохраняется в истории Git**, но больше не загромождает актуальное дерево.
Основные рабочие скрипты прежних экспериментов и подробные документы
в \`docs/\` оставлены ради воспроизводимости.

Дублирующиеся правила \`.gitignore\` объединены в один файл. Все
оригинальные снимки, ручные маски, веса моделей, SQLite, отчёты, CSV
экспериментов, \`data/\`, \`models/\`, \`reports/\` и \`checkpoints/\`
**остаются вне Git**. Уже отслеживаемые пустые \`.gitkeep\` сохранены.

## Проверка на компьютере

~~~powershell
git switch feature/gpu-batch-resume
git pull --ff-only origin feature/gpu-batch-resume
git status --short
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_inference_boundary.py" -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_batch_v4.py" -v
~~~

Если \`git status --short\` показывает личные изменения, не выполняй
\`git clean -fdx\` и не удаляй \`data/\`, \`models/\`, \`reports/\`.
Если изменён старый README_STAGE и Git не даёт сделать fast-forward,
сначала сохрани свои заметки в отдельное место; \`git pull\` может
потребовать ручной разбор.

## Как восстановить старую заметку

История не удалена и main не изменён. Например:

~~~powershell
git show HEAD~1:README_STAGE14.md
~~~

Команда демонстрирует принцип: при дальнейших коммитах путь \`HEAD~1\`
может больше не указывать на исходный коммит удаления, поэтому для
точного восстановления ищи его через \`git log --all -- README_STAGE14.md\`.

Не изменять замороженные модели или завершённые TEST-отчёты при уборке
репозитория. PR #1 остаётся черновиком, слияние в \`main\` отдельно.
