# CloudVision AI — targeted cloud-heavy challenge, NOT random TEST

**Цель:** дополнительно проверить правило «ОТСЕЯТЬ, если доля облаков
СТРОГО >75%». Ровно 75.000% = «СОХРАНИТЬ».

Ранее два независимых TEST (5 и 24 снимка) **не содержали ни одного
эталонного REJECT (>75%)**. Пилотные 30 масок имели AI-подсказку, поэтому
для проверки эффективности отсечения нужны *новые, ещё не использованные
кадры* с независимой ручной разметкой.

Важно: выбор кандидатов **по визуально высокой облачности** делает такой
набор **целенаправленным/смещённым**, а не случайным репрезентативным
тестом всех 4207 фотографий. Не смешивать его метрики с 24 кадрами
случайного TEST.

## Шаг 1. Построить локальную галерею новых кандидатов без AI

    git pull --ff-only origin feature/gpu-batch-resume
    .\.venv\Scripts\python.exe prepare_cloud_heavy_challenge.py browse --count 100
    Start-Process .\reports\v5\cloud_heavy_pool\index.html

Инструмент случайно выбирает до 100 оригинальных фотографий (до 2 из
одной новой группы дата/камера), исключая *по группе* исторические
TRAIN/VAL/TEST, v4 TRAIN/VAL/TEST, 30 пилотных кадров, 24 новых TEST и
предыдущий предпросмотр, если его CSV существует.

Если новых групп недостаточно для 100 кандидатов, выбирает все
доступные в пределах лимита; если осталось меньше пяти групп, выдаёт
ошибку. Изображения читаются только для миниатюр и не меняются. В
HTML **нет AI-масок, облачных процентов, нейросети и внешних запросов**.

## Шаг 2. Человек выбирает 10–15 потенциально облачных сцен

В HTML отметь флажками снимки, на которых облака визуально занимают
большую часть. Не путай облака со снегом/льдом, горными вершинами,
бликами на воде, песком и другими светлыми объектами.

**Максимум один кадр одной группы дата/камера**: галерея для удобства
может показывать два изображения одной группы, но скрипт не разрешит
взять оба в один challenge.

Нажми «Скачать selected_cloud_heavy.txt» и положи скачанный
\`selected_cloud_heavy.txt\` **в корень репозитория**. Там будет по
одному относительному имени фотографии в строке. Не редактируй
предыдущие фиксированные CSV или веса.

Если нет хотя бы пяти действительно подходящих новых сцен, **не
подменяй их старыми TEST** — сообщи об этом в отчёте или собери новые
снимки.

## Шаг 3. Зафиксировать именно этот целевой список

    .\.venv\Scripts\python.exe prepare_cloud_heavy_challenge.py freeze

Создастся \`reports/v5/cloud_heavy_challenge/challenge_manifest.csv\`
и \`protocol.json\` с описанием целевого, не случайного отбора.
Скрипт проверяет путь, точное присутствие в исходном пуле,
дубликаты, отсутствие защищённых групп и не позволяет перезаписать
ранее зафиксированный challenge.

**После этого не изменяй выбранный список.**

## Шаг 4. Зафиксировать SHA-256 обеих старых моделей

Перед разметкой и до любых предсказаний:

    .\.venv\Scripts\python.exe evaluate_v5_holdout.py --freeze --manifest reports/v5/cloud_heavy_challenge/challenge_manifest.csv --out reports/v5/cloud_heavy_challenge/evaluation

Эта команда НЕ открывает RGB-пиксели challenge и не запускает U-Net;
создаёт отдельный \`evaluation/frozen_models.json\`. Старые
\`models/cloudvision_unet_v4_policy.pt\` и
\`models/cloudvision_unet_v5_pilot.pt\` не изменяй.

## Шаг 5. Независимая ручная разметка без AI

    .\.venv\Scripts\python.exe label_with_ai_fast.py --input data/new_raw --manifest reports/v5/cloud_heavy_challenge/challenge_manifest.csv --splits test --blind --out data/cloud_heavy_verified --log reports/v5/cloud_heavy_challenge/label_log.csv

Создаются **новые** ручные PNG размера исходных снимков с бинарными
значениями 0/255, отдельно от TRAIN/VAL/TEST. Не используй AI-подсказки.
После сохранения всех выбранных масок проверь количество:

    (Get-ChildItem data/cloud_heavy_verified -Recurse -Filter *.png -File).Count

Если вручную оказалось меньше 75% облаков на части кадров, **не удаляй
такие кадры из заранее зафиксированного challenge**. Иначе оценка
получится выборочно завышенной.

## Шаг 6. Сравнить уже зафиксированные v4 и v5 ОДИН РАЗ

    .\.venv\Scripts\python.exe evaluate_v5_holdout.py --evaluate --device cuda --manifest reports/v5/cloud_heavy_challenge/challenge_manifest.csv --labels data/cloud_heavy_verified --out reports/v5/cloud_heavy_challenge/evaluation

Получишь \`evaluation/summary.csv\` и \`per_image.csv\`:
MAE, IoU, корректные решения, **reference_rejects**, **missed_rejects**,
**wrong_rejects**. Прежде всего сравни число реально облачных кадров
по ручной разметке и число пропущенных отсевов.

**Отчётное название:** «Целевая проверка сильно облачных сцен, отобранных
визуально оператором, с независимой слепой разметкой».

Это НЕ новая оценка типичной точности на всех 4207 фото. Никогда
не используйте результаты для подбора порога/эпох на этих же кадрах
и не запускайте автоматическое удаление оригиналов. PR и main не меняют
данные/модели. Папки data/, models/, reports/ и TXT с локальными именами
не должны попадать в Git.


## Поиск конкретного снимка и ручной маски для визуального аудита

После однократной оценки можно **только просмотреть** самый сложный
кадр. Для этого есть отдельный безопасный локатор:

    git pull --ff-only origin feature/gpu-batch-resume
    .\.venv\Scripts\python.exe find_cloud_heavy_case.py
    Start-Process .\reports\cloud_heavy_case_review\2025-11-30_22-18-23_SXC3-2334_1_original_manual_preview.jpg

Скрипт ищет оригинал в \`data/new_raw\`, а PNG-маску — в
\`data/cloud_heavy_verified\`, включая вложенные папки. Выводит точные
пути и ручной процент облачности. В отдельной папке \`reports/\`
создаёт только уменьшенную JPG-композицию из трёх частей:
**RGB / ручная бинарная маска / розовое наложение ручной маски**.

Для произвольного кадра:

    .\.venv\Scripts\python.exe find_cloud_heavy_case.py --query SXC3-2334

Если найдены несколько кадров с таким фрагментом имени, программа
печатает список и **не выбирает автоматически** какой-то один.
Перезапись готового превью запрещена: для повторного снимка укажи
новую папку \`--out reports/cloud_heavy_case_review_2\`.

Не изменяй и не заменяй вручную сохранённые challenge-маски **после**
фиксации результатов: при выявлении проблемы в исходном эталоне
задокументируй её отдельно и сохрани исходный отчёт испытаний.


## Диагностика одного уже оценённого кадра: RGB / ручная маска / v4 / v5

После завершения целевого challenge (первоначальный
\`evaluation/summary.csv\` не изменять) создай **только визуальное**
сравнение сохранённых моделей:

    git pull --ff-only origin feature/gpu-batch-resume
    .\.venv\Scripts\python.exe compare_cloud_heavy_models.py --device cuda
    Start-Process .\reports\cloud_heavy_case_review\2025-11-30_22-18-23_SXC3-2334_1_v4_v5_comparison.jpg

Новый JPEG содержит **четыре панели** с одинаковым оригинальным RGB:
1. исходное изображение;
2. ручная маска, наложенная полупрозрачным розовым цветом;
3. предсказанная v4 маска, розовым;
4. предсказанная v5 маска, розовым.

Подписи включают **точные** проценты по исходному размеру бинарных масок
(0/255) и решение >75%. Для проверки других уже оценённых challenge
снимков передай \`--query ПОЛНОЕ_ИМЯ_ФАЙЛА\`.

Перед инференсом проверяются SHA-256 исходного зафиксированного
\`challenge_manifest.csv\` и обеих моделей по **существующему**
\`reports/v5/cloud_heavy_challenge/evaluation/frozen_models.json\`.
Программа откажется выбирать кадр вне этого манифеста и не даст писать
в папки изображений, масок, моделей или предыдущей оценки. Результат
создаётся только как новый JPEG; перезапись не разрешена. Для
повторной диагностики укажи другой \`--out\`, например
\`--out reports/cloud_heavy_case_review_2\`.

Это **инспекция ошибок после TEST**, а не новая независимая оценка.
Не меняй веса, порог, ручные маски или уже сохранённые TEST-метрики
на основе этой картинки. Спорные эталоны можно документировать отдельно.
