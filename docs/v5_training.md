# CloudVision AI v5 — пилотные исправления, защита выборок и новый TEST

## Почему нужен v5

В пилоте 30 кадров U-Net v4 предложила сохранить все 30. После
ручной проверки оператором появились три эталонных решения «ОТСЕЯТЬ»
(прогнозы 72.31%, 71.30%, 67.66%, ручные значения >75%).
Также обнаружена сильная ложная маска на рельефе: прогноз 44.38%,
ручная разметка 7.85%. В предыдущем независимом TEST из 5 кадров не
было ни одного эталонного примера >75%.

Эти 30 **AI-assisted** исправленных масок допустимо использовать для
дообучения, но **не для независимой оценки качества**. Предыдущий TEST
сохраняем в архиве и не используем для настройки v5.

## 1. Проверить пилот и составить TRAIN без утечек

    git pull --ff-only origin feature/gpu-batch-resume

    .\.venv\Scripts\python.exe prepare_v5_plan.py

Команда НЕ обучает сеть и не меняет исходные файлы. Она сверяет:
- старый split: только старый TRAIN, старые VAL/TEST защищены;
- v4 selection: новые TRAIN=35, VAL=10, TEST=5;
- операторский пилот (30 строк) и сохранённые ручные PNG 0/255;
- имена, группы дата/камера, соотношение сторон старых масок;
- одинаковые пути между PILOT и TRAIN: при совпадении исходных байтов
  более свежая пилотная маска **заменяет старую запись**, а не дублирует её;
- группы PILOT, пересекающиеся со старым или v4 VAL/TEST,
  **целиком исключаются из TRAIN**.

Если одинаковое имя содержит разные исходные изображения, сборка
останавливается, а не смешивает их. Параметры и старый split не меняй
ради прохождения проверки: лучше разобраться с конфликтами.

Результаты:
- \`reports/v5/preflight/train_manifest.csv\` — пары для TRAIN и
  старая VAL (полные пути на этом ПК);
- \`reports/v5/preflight/excluded_pilot.csv\` — исключённые и
  заменённые дубликаты;
- \`reports/v5/preflight/summary.json\` — реальные количества.

Если preflight уже выполнен, он не перезаписывает план; для нового
эксперимента используйте отдельный \`--out\`. Не добавляй пилотные
картинки в исходную v4 VAL.

## 2. До обучения зафиксировать ещё не виденную проверку v5

    .\.venv\Scripts\python.exe select_v5_holdout.py --count 24

Скрипт **не запускает нейросеть и не читает пиксели**: равновероятно
выбирает 24 разные группы дата/камера и по одному имени кадра в каждой.
Исключает все группы прежнего старого TRAIN/VAL/TEST, v4 TRAIN/VAL/TEST,
пилота и раннего предпросмотра пяти снимков (если отчёт существует).

Файл \`reports/v5/holdout_manifest.csv\` создаётся один раз; повторная
запись запрещена. Не просматривай эти кадры для подбора параметров
и **не добавляй их в TRAIN**.

Важно: 24 случайные сцены НЕ гарантируют эталонных кадров >75%.
Сначала используем эту выборку для честной общей оценки. Для отдельной
проверки отказов можно дополнительно сформировать **непредставительную
сложную выборку** (cloud-heavy challenge), размеченную вручную без
AI-подсказок. Её результаты нужно публиковать отдельно, не подменяя
случайную проверку.

## 3. Тренировка v5 на RTX 3060 Ti, после успешных шагов 1 и 2

Короткая проверка (новые пути, ничего не перезаписывает):

    .\.venv\Scripts\python.exe train_cloudvision_v5.py --device cuda --epochs 2 --model models/cloudvision_unet_v5_smoke.pt --out reports/training_v5_smoke

Если она завершилась без ошибок:

    .\.venv\Scripts\python.exe train_cloudvision_v5.py --device cuda --epochs 18 --size 256 --batch-size 4 --model models/cloudvision_unet_v5_pilot.pt --out reports/training_v5

Используем веса уже выбранной v4 Policy (эпоха 19), lr=0.00008,
раннюю остановку после 6 эпох без улучшения. У примеров PILOT повышен
вес (4), у старых новых TRAIN v4 вес 2, у исторических TRAIN вес 1.
Пары изображение/маска из preflight перед запуском сверяются повторно;
совпадение групп с новым TEST не допускается. TEST-картинки/маски не
открываются.

Сохраняются:
- \`models/cloudvision_unet_v5_pilot.pt\` — отдельные веса v5;
- \`reports/training_v5/training_history.csv\` — динамика VAL по эпохам;
- \`reports/training_v5/model_comparison.csv\` — v4 и v5 по прежним
  10 VAL (MAE, IoU, решение по строго >75%);
- \`reports/training_v5/validation_predictions_v5.csv\` — подробные
  прогнозы в исходном разрешении.

**Нельзя заявлять, что v5 стала точнее на новом TEST по данным VAL.**
Прежнюю VAL уже использовали для настройки v4, поэтому новые VAL
результаты могут оказаться оптимистичными.

## 4. После обучения: финальная независимая проверка

Сначала окончательно выбрать checkpoint по VAL, зафиксировать v4 и v5
SHA-256 **ДО просмотра нового TEST**:

    .\.venv\Scripts\python.exe evaluate_v5_holdout.py --freeze

Команда создаст \`reports/v5/final_holdout/frozen_models.json\`.
Она не открывает пиксели новых TEST-снимков и не загружает нейросеть.
Если checkpoint изменится после фиксации, проверка не выполнится.

После этого вручную разметить новые 24 TEST **без AI-подсказок**.
Для просмотра подойдет редактор:

    .\.venv\Scripts\python.exe label_with_ai_fast.py --input data/new_raw --manifest reports/v5/holdout_manifest.csv --splits test --blind --out data/v5_holdout_verified --log reports/v5/holdout_label_log.csv

НЕЛЬЗЯ запускать предсказания на новых TEST до завершения ручной
разметки. Когда сохранены **все 24** бинарные ручные маски исходного
разрешения, запусти сравнение **один раз**:

    .\.venv\Scripts\python.exe evaluate_v5_holdout.py --evaluate --device cuda

Скрипт сверит SHA-256 двух замороженных моделей, размеры и бинарность
всех масок, затем создаст:
- \`reports/v5/final_holdout/per_image.csv\` — по каждому снимку v4 и v5;
- \`reports/v5/final_holdout/summary.csv\` — MAE, IoU, точность отсева,
  ложные отсеивания и пропущенные отсеивания, число реально облачных
  снимков по ручным маскам.

Отчёт не перезаписывается. При плохом результате нельзя подбирать
новую эпоху или порог по этим же TEST и снова называть их независимыми.
Если на 24 случайных снимках снова мало ручных примеров >75%, это
ограничение следует честно отразить и отдельно сформировать
набор challenging cloud-heavy, не выдавая его за случайный TEST.

**Текущий статус:** подготовлены скрипты отбора и обучения; реальная
проверка групп и запуск GPU возможны только на ПК, где находятся фото,
ручные маски и checkpoint. Все модели v3/v4 остаются неизменными.
