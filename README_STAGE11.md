# CloudVision AI — этап 11: диагностика и U-Net v2

## Почему этап нужен

Предыдущая модель Stage 10 предсказывала 100% облачности для каждого из 16 тестовых снимков. Это **коллапс предсказаний**, а не успешная сегментация. Кроме того, лучший вес выбирался по val loss, хотя валидирующая ошибка процента облаков могла быть ниже у другой эпохи.

## Перед началом

Не удаляй предыдущие файлы, обученную модель и изображения. Должны существовать `train_cloudvision.py`, папки `data/input`, `reports/labels`, а также `reports/training/dataset_split.csv`.

1. Распакуй архив и скопируй `diagnose_unet.py` и `train_cloudvision_v2.py` рядом с `train_cloudvision.py` в корень проекта.
2. Скопируй `tests/test_stage11.py` в папку `tests`.
3. В PowerShell VS Code, открытом в корне проекта, запусти:

```powershell
.\.venv\Scripts\python.exe diagnose_unet.py
```

Это проверит **train и val**, но не тестовые снимки. Пришли вывод диагностики.

## Исправленный эксперимент обучения

```powershell
.\.venv\Scripts\python.exe train_cloudvision_v2.py --epochs 30
```

Для более ограниченного компьютера (уменьшение размера теряет детали облаков):

```powershell
.\.venv\Scripts\python.exe train_cloudvision_v2.py --epochs 25 --size 128 --batch-size 2
```

### Что изменено

- Новый файл `models/cloudvision_unet_v2.pt`; старая модель **не перезаписывается**.
- Используется более мягкий вес Dice, плюс штраф за разницу средних долей облаков (мягких вероятностей) и инициализация смещения выходного слоя.
- Больше эпох; по каждой выводятся валидационная MAE, IoU, точность порога и диапазон прогнозов.
- Лучший файл выбирается **только по валидации**, при этом предпочитается модель, которая не размечает все снимки одним классом. Это экспериментальная эвристика, а не гарантированное улучшение.
- Группа `test` **не используется** для подбора параметров и не открывается. Для честной итоговой оценки потребуется новый независимый тест после завершения настройки (старые тестовые метрики уже были просмотрены).
- Нет автоматического копирования или удаления снимков.

### Файлы результата

- `reports/training_v2/validation_predictions.csv`

### Тесты кода

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Если валидационные прогнозы снова равны 0% или 100% для всех снимков, не подключай модель к сортировке: это признак недостаточного обучения или ошибок в данных/функции потерь. Следующий шаг — проверить ручные маски, рассмотреть предобученную модель и переобучение на фрагментах.
