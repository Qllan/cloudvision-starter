# CloudVision AI — этап 3: проверяем качество распознавания

Этот этап нужен, чтобы **не выдавать ошибки нейросети за правильные данные**.

На первых трёх примерах модель CLIPSeg заметно путает участки суши с облаками.
Не включай автоматическое удаление файлов до проверки точности!

## Как установить (Windows 11)

1. Скопируй `run_ai.py`, `label_clouds.py` и `evaluate_ai.py` из архива
   в корень **твоего существующего проекта** (там, где `main.py`).
2. Подтверди замену **только** `run_ai.py`. Старые фотографии и остальные
   папки оставь как есть.
3. Скопируй `tests/test_quality.py` в имеющуюся папку `tests`.
4. Запусти в терминале VS Code по порядку:

```powershell
.\.venv\Scripts\python.exe run_ai.py --limit 3
.\.venv\Scripts\python.exe label_clouds.py
```

### Как пользоваться редактором разметки

Откроется обычное окно с первым снимком.

- **Левая кнопка мыши** — закрашивай зелёным только облака, а не снег,
  светлые горы, песок, воду или другие участки суши.
- **Правая кнопка** — стирай случайные штрихи.
- **Кисть + / Кисть −** — меняй толщину для больших и мелких облаков.
- **Сохранить / S** — сохраняет маску ручной разметки. После этого
  переходи к следующему изображению.

Для первого эксперимента достаточно размечать **три снимка**, но даже
несколько разметок не дают полноценной статистики точности. Нужны
разнообразные снимки и дальнейшая независимая проверка.

### Получи отчёт о качестве

Закрой окно разметки, затем введи:

```powershell
.\.venv\Scripts\python.exe evaluate_ai.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Появится файл `reports/evaluation.csv` с колонками:

- `model_percent` — доля облаков согласно модели;
- `manual_percent` — доля по твоей ручной разметке;
- `absolute_error_pp` — абсолютная ошибка в **процентных пунктах**;
- `cloud_iou` — насколько совпали облачные области (от 0 до 1, где 1 — идеально);
- `same_75_percent_decision` — совпало ли решение при пороге 75%.

В `reports/masks` теперь сохраняются исходные **маски модели**, а не только
полупрозрачные превью. В `reports/labels` находятся ручные маски.

## Какие данные не надо публиковать в GitHub

Не добавляй исходные снимки, `.venv`, кэш моделей, папку `reports` и файлы с
результатами в публичный репозиторий без проверки правил использования данных.
Код `run_ai.py`, `evaluate_ai.py`, `label_clouds.py`, `tests` и этот README
публиковать можно. Избегай добавления чужих моделей в репозиторий.

## Важно

* Ручная маска — **приближённая**, это не профессиональная экспертная разметка.
* Снимки в JPEG/RGB отличаются от тех, на которых обучалась исходная модель.
* Показатель IoU и ошибка по проценту помогают определить проблему, но не
  исправляют её автоматически. Исправление модели — следующий этап.
* Удаление файлов по порогу 75% пока НЕ включено.
